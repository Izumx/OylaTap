# «Сегодня»: продолжение темы — 15.10.2026

Итерация И1 из [продуктового разбора](PRODUCT_AUDIT_2026-10-15.md). Ученик получает небольшую сохраняемую сессию, а длинная тема продолжается за пределами первых трёх серий.

## Поведение для ученика

- На день выбирается до трёх серий. Набор хранится в PostgreSQL и одинаков на разных устройствах после входа в тот же аккаунт. Школьный и свободный режимы имеют отдельные наборы.
- Серия исключается из следующих порций после просмотра и хотя бы одного верного микровопроса. Учитывается прежний прогресс, в том числе ответы прошлых дней. Просмотр и ответ остаются отдельными сигналами, баллы теста и оценка пересказа не меняются.
- Повторное открытие продолжает с первой незавершённой серии сохранённого набора. Если весь набор завершён, сразу открывается его итог. Перезагрузка не подгружает ещё три ролика.
- Следующий день определяется сервером по `Asia/Qyzylorda` (UTC+5). Например, тема из пяти серий проходит как 1–3, затем 4–5. Если из второй порции завершена только четвёртая серия, следующая порция начнётся с пятой.
- Незавершённые серии остаются в очереди. После завершения темы, явно выбранной учителем, интерфейс предлагает тест, пересказ или просмотр прогресса. Тема учителя не заменяется автоматически другой темой.
- Продолжить раньше можно самостоятельно: кнопка «Продолжить тему сейчас» открывает следующую серию полного маршрута. Это не создаёт новую автоматическую дневную порцию.
- Причина выбора видна рядом с видео, в том числе на телефоне: тема класса, задание учителя, личный выбор, повторение или библиотека. На широком экране дополнительно показано название класса.
- Итог различает конец короткой сессии и следующий шаг темы. До завершения сессии главная кнопка возвращает к оставшимся сериям. Итоговый тест по-прежнему можно открыть заранее.
- При возврате во вкладку приложение проверяет обновление дня и темы учителя. Переход суток в открытой вкладке проверяется раз в минуту. При смене размера экрана сохраняется выбранная серия или итог сессии.

Без входа доступен просмотр, но постоянная дневная сессия гостя не создаётся. Локальная проверка понимания гостя не выдаётся за сохранённый учебный результат.

## Выбор темы и задания

Порядок в школьном режиме: явно указанная тема класса → невыполненное задание → личная тема → подходящая незавершённая тема библиотеки. Среди незавершённых заданий сначала выбирается ближайшее по сроку; просроченное незавершённое задание остаётся доступным и не исчезает из списка.

Для автоматического выбора задание считается отправленным, если все его серии просмотрены и есть хотя бы одна попытка итогового теста. Это **критерий сдачи**, а не утверждение об усвоении и не порог балла. Низкий результат остаётся в отчётах и может привести к повторению в свободном режиме. Пересказ пока не входит в обязательный критерий: у задания ещё нет настройки обязательности пересказа.

Изменение результата теста или появление другого автоматического предложения не заменяет уже выбранный набор в тот же день. Явная смена темы учителем или смена личной темы пересчитывает соответствующий набор; права на закрытую тему проверяются при каждом обращении. Уже опубликованные темы остаются неизменяемыми.

Если ученик участвует в нескольких классах с указанными текущими темами, сохраняется существующее правило: выбирается наиболее недавно созданный класс. Выбор контекста самим учеником и полный жизненный цикл заданий относятся к последующим итерациям.

## Изменения хранения

Добавочная миграция `005_daily_sessions.sql` создаёт `daily_sessions` с ключом `(user_id, session_date, mode)` и индексами для выборки прогресса. Она не переписывает исходные таблицы прогресса, попытки, пользователей и задания. В список `scripts/migrate.ts` добавлен новый шаг; повторный запуск пропускает уже применённую миграцию.

Выбор набора выполняется в короткой транзакции с блокировкой для конкретного аккаунта. Параллельные запросы двух устройств получают один набор. Контекст явной темы хранится вместе с выбором, поэтому указание учителя может переопределить прежний личный выбор. При удалении пользователя его дневные сессии удаляются по внешнему ключу.

Не требуется запускать seed, пересоздавать контейнер, менять `.env` или переносить базу. Для обновления существующей установки: выполнить `npm run db:migrate`, `npm run build`, перезапустить приложение. Существующая база и папка медиа сохраняются.

## Проверка

`tests/daily.spec.ts` добавляет семь сценариев с настоящей PostgreSQL:

1. Параллельное создание, повторный вход, второе устройство, завершение порции и тот же набор после перезагрузки; итог на русском и казахском, размеры 390×844 и 360×740.
2. Последующие порции темы из пяти серий, перенос незавершённого и сохранение темы учителя после прохождения.
3. Раздельный учёт просмотра и верного ответа, использование старого прогресса.
4. Старое сданное задание не скрывает новое; сдача текущего не открывает новую автоматическую порцию сегодня.
5. Явная тема учителя выше личной; режимы независимы; при потере доступа закрытая тема не возвращается из сохранённой сессии.
6. Возобновление незавершённой серии в интерфейсе, видимая причина выбора на телефоне, ранний доступ к тесту, верный ответ и перезагрузка.
7. Возврат в открытую вкладку после смены дня или темы учителем.

Для моделирования следующего дня тесты перемещают только ключи собственных временных дневных сессий в прошлое. Системное время, существующие учебные данные и даты пользовательских ответов не меняются. Тестовые темы ссылаются на уже существующий MP4; новые учебные видео не производятся. У временных аккаунтов отдельные подключения к базе, после проверки их строки удаляются.

Дополнительно проверены применение всех пяти миграций на отдельной пустой PostgreSQL и повторное применение, сохранение дневного набора и результата после реального перезапуска production-сервера, контрольные отпечатки исходных учебных записей и локальных файлов конфигурации. Полный набор содержит 21 автоматический сценарий, включая прежние 14.

Результат контрольного прогона на Windows/Edge: **21/21, 18,5 секунды**. TypeScript, production-сборка и общая проверка Prettier прошли. После тестов исходные строки всех 11 предметных таблиц совпали с контрольными отпечатками, три локальных файла конфигурации/аккаунтов не изменились. В реальной сессии владельца главная лента начала с оставшихся второй и третьей серий; видео поставлено на паузу без изменения прежнего прогресса.

Снимки проверки находятся только локально: `.local/qa/daily-session-end-desktop.png`, `daily-session-end-mobile.png`, `daily-session-end-kazakh.png`. Это проверочная тема, а не новый опубликованный учебный материал.

Настройка Prettier `endOfLine: auto` сохраняет принятые окончания строк файлов на Windows и позволяет проверять оформление без массового изменения прежних файлов. Изменений библиотек и зависимостей нет.
