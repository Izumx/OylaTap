# OylaTap

Первая рабочая версия образовательной PWA по [концепции 2.0](<Concept 2.0>). Основной экран — тёмная вертикальная лента: свайп между сериями, тест и пересказ рядом с видео. Интерфейс адаптирован для телефона и компьютера, основные сценарии доступны на русском и казахском.

## Что работает

- Аккаунты ученика и учителя, вход, выход, настройки профиля. Пароли хешируются с scrypt, сессии хранятся в PostgreSQL, cookie — HttpOnly.
- Видео занимает главный экран: свайп, действия справа, навигация снизу на телефоне. На компьютере блок «О теме» можно скрыть; есть перемотка и пауза пробелом. «Спокойный режим» по умолчанию приглушает акценты и уменьшает декоративную анимацию; настройки оформления и фокуса сохраняются на устройстве.
- Страница темы с маршрутом «серии → тест → пересказ»: продолжение с первой непросмотренной серии, отдельные статусы просмотра и проверки знаний. После ошибки в тесте можно открыть связанную серию; в прогрессе есть следующий шаг для начатой темы. Пересказ остаётся добровольным, если его не назначил учитель.
- Конечная лента «Сегодня»: до трёх роликов, микровопрос после каждого и итог сессии без автоподгрузки. Школьный режим учитывает текущую тему класса, свободный — слабые темы и интересы. Лента с настоящим воспроизведением MP4, свайпом, навигацией клавишами и планом сезона. Библиотека с поиском и фильтрами по предмету, языку и классу.
- Микровопросы по сериям и итоговые тесты с проверкой на сервере, объяснением ошибок, повторной попыткой и сохранением прогресса. Правильные ответы не выдаются ученику до отправки теста.
- Запись пересказа до двух минут, прослушивание, согласие на сохранение, ручной текст, отзыв и оценка учителя, удаление собственной записи.
- Учитель задаёт текущую тему всему классу, ученик — себе. Настраиваются интересы и одно напоминание в день в выбранное время (UTC+5), с тихим периодом 21:00–08:00. Сейчас напоминания работают при открытом приложении; доставка при закрытом приложении через Web Push ещё не подключена.
- Классы и коды приглашения, задания и сроки. Просмотр, тест и оценка пересказа показаны отдельно; есть экспорт CSV.
- Студия: PDF с текстом / TXT / MD → редактируемые серии и вопросы → MP4 из Google Flow или фоновая сборка карточек с текстом → предпросмотр → подтверждение публикации → назначение классу.
- Сезоны учителя по умолчанию доступны только назначенным классам. Открытую публикацию в библиотеке учитель выбирает явно. Запись ученика доступна ему и учителю назначившего класса.
- Опциональный адаптер Ollama для настоящего ИИ-черновика сценария и вопросов. Ответ проверяется по схеме и сначала предлагается учителю для редактирования.
- PWA-манифест, иконки и service worker с экраном отсутствия сети. Видео и личные результаты не кешируются на общем устройстве.

Демо: четыре направления, 12 коротких MP4-карточек без озвучки, класс и задание. Это примеры формата, а не проверенная школьная библиотека.

## Запуск

**Адрес `127.0.0.1` доступен только на том компьютере, где запущен сервер.** Сервер из облачной задачи Codex не появляется автоматически на вашем ПК. Для открытия сайта в браузере ПК скачайте эту ветку проекта и запустите её на том же ПК.

**Первый запуск Windows:** скачайте [ZIP с кодом MVP](https://github.com/Izumx/OylaTap/archive/refs/heads/mvp/tiktok-postgres.zip), распакуйте его и откройте `INSTALL-WINDOWS.cmd`. Установщик через Windows Package Manager скачает недостающие Node.js LTS, Docker Desktop и FFmpeg, обновит PATH, запустит Docker Desktop и дождётся движка. Затем он установит зависимости проекта, поднимет PostgreSQL, подготовит демо и откроет сайт в браузере. Окно сервера нужно оставить открытым.

Windows может запросить подтверждение установки и настройку WSL / перезагрузку для Docker Desktop. После перезагрузки снова откройте `INSTALL-WINDOWS.cmd`: установленные компоненты пропускаются. Если `winget` отсутствует, установщик откроет официальную страницу «Установщика приложений» Microsoft. Проверка хешей пакетов остаётся включённой. Автоматический установщик Windows подготовлен в облачной Linux-среде; на физическом ПК Windows его выполнение ещё не проверено.

Для следующих запусков откройте Docker Desktop, затем `START-WINDOWS.cmd` в распакованной папке проекта. Он подготовит базу и откроет браузер. При отсутствии компонента появится конкретное сообщение.

Если компоненты ещё не установлены, их можно установить из PowerShell через Windows Package Manager:

```powershell
winget install --exact --id OpenJS.NodeJS.LTS
winget install --exact --id Docker.DockerDesktop
winget install --exact --id Gyan.FFmpeg
```

После установки закройте терминал, откройте Docker Desktop и дождитесь запуска движка. Если Docker запросит настройку WSL или перезагрузку, завершите её перед запуском проекта. Затем откройте `START-WINDOWS.cmd`. Помощник проверен в облачной Linux-среде; запуск на физическом ПК Windows требует проверки на вашем устройстве.

Во всех ОС можно запустить из корня проекта:

```bash
node scripts/local-start.mjs
```

Проверка установленных компонентов без установки зависимостей и запуска сервера: `node scripts/local-start.mjs --check`.

Требуются **Node.js 22.12+**, npm, Docker Compose, **FFmpeg и FFprobe** в PATH. В облачной среде проверено с Node.js 24 и PostgreSQL 17. База приложения — исключительно PostgreSQL.

Из корня репозитория:

```bash
bash scripts/setup.sh
npm run dev
```

Приложение использует порт `3000`. На странице входа есть «Попробовать как ученик» и «Попробовать как учитель». Для отдельного аккаунта выберите «Создать аккаунт». Демо-аккаунты общие: изменения видны другим посетителям демо.

Ручные шаги, в том числе для Windows с установленным Docker Desktop:

```bash
npm ci
# Скопируйте .env.example в .env, если .env ещё отсутствует.
docker compose up -d db
npm run db:migrate
npm run db:seed
npm run dev
```

Миграции и сид повторяемы. Сид разрешён только при `DEMO_MODE=true`; существующие сезоны и пользовательские результаты не сбрасываются. `scripts/setup.sh` сохраняет существующий `.env`. Для внешней PostgreSQL задайте `DATABASE_URL` и запускайте `SKIP_LOCAL_DB=1 bash scripts/setup.sh`.

```bash
npm run build          # TypeScript и production-сборка
npm start              # сервер с собранным интерфейсом
npm test               # браузерные и API-проверки с реальной PostgreSQL
npm run format:check
```

Тесты используют системный Chromium (`CHROMIUM_PATH` для другого расположения), порт 3000, демо-сезоны и отдельные временные аккаунты. Они удаляют только созданные ими записи. Для браузерных тестов микрофон эмулируется Chromium. Не запускайте тесты на базе реальной школы.

## Данные и процессы

`DATABASE_URL` задаёт подключение. Docker Compose хранит данные в томе `postgres_data`; `docker compose down` сохраняет том, `down -v` удаляет его. Тексты, ответы и результаты находятся в PostgreSQL. Видео и аудио — в `DATA_DIR` (по умолчанию `.local/uploads`), путь и права доступа — в базе. При переносе нужны и база, и каталог медиа.

После перезапуска нужно снова поднять PostgreSQL и приложение. Сборка видео, прерванная перезапуском, получает статус ошибки; сценарий сохранён и можно повторить сборку. Фоновая сборка пока работает в процессе приложения, а не в отдельной распределённой очереди. В новой облачной машине сохранность Docker-тома нужно проверить; для демо при отсутствии базы можно повторить миграции и сид. Восстановление после публикации облачного снимка ещё не проверено.

Для HTTPS задайте `COOKIE_SECURE=true`. Запись с микрофона требует HTTPS или локального защищённого контекста браузера. Для реального пилота используйте отдельную базу, свои закрытые учётные данные PostgreSQL и `DEMO_MODE=false`. Не переносите учебные данные детей в общие демо-аккаунты.

## Локальный ИИ и Google Flow

См. [подключение локального ИИ и производство видео](docs/LOCAL_AI.md). В текущей облачной среде Ollama не запущена: кнопка ИИ-черновика отключена до подключения. Контракт адаптера проверен автоматическим тестом; качество реальной модели на ПК основателя пока не проверялось.

Подписка Google Flow используется через создание и экспорт MP4, затем загрузку в серию. Автоматическое API-подключение Flow не заявляется. Приложение проверяет MP4/H.264, длительность до трёх минут и размер до 80 МБ.

## Что ещё нужно до школьного пилота

Это рабочая итерация MVP, а не готовый публичный запуск. Распознавание речи, предварительная ИИ-оценка пересказа, озвучка и генерация иллюстраций ещё не подключены. Для видео пока есть импорт готовых роликов и карточки с текстом. Сканы PDF требуют отдельного OCR.

Нужно согласовать первые классы и темы, проверить контент с педагогом, качество казахской озвучки и распознавания, а также роли школы, необходимые согласия, сроки хранения, размещение и резервное копирование данных. Формальное согласие родителя/школы не заменяется флажком записи. Восстановление пароля, проверка email, управление школой, автоматическое удаление по сроку и устойчивая очередь генерации — следующие задачи. Офлайн-сезоны остаются вне первой версии.

Проверки включают TypeScript, production-сборку, установку с чистой PostgreSQL, четырнадцать автоматических браузерных/API-сценариев, адаптивность и экран отсутствия сети. Маршрут и лента проверяются с реальной PostgreSQL на Windows через Microsoft Edge, включая продолжение просмотра, возврат к серии после ошибки, сохранение результата после перезагрузки, перемотку, управление пробелом и настройки оформления. Контракт Ollama проверяется с тестовым сервером; реальная модель и доставка фоновых уведомлений ещё не проверены. GitHub Actions настроен, результат удалённого запуска нужно смотреть отдельно.
